<h2>按「什么时候失败」分类，比按现象分类更快</h2>
<p>连接失败的现象很多：完全打不开、提示超时、能连但没网、用几分钟就断。但这些现象背后的原因常常重叠，按现象查容易绕圈。</p>
<p>更有效的方式是按「失败的时间点」分类：配置完立刻失败、运行几分钟后失败、运行几小时后失败、偶尔失败。四个时间点对应四类原因，排查路径完全不同。</p>

<h2>配置完立刻失败：配置本身有问题</h2>
<p>四成的情况是这四件事：端口填错、协议选错、凭据带了空格、防火墙没放行。这四项都是「一步之差」，改对就好。</p>
<p>排查顺序：先用供应商给的原始信息逐字符核对，再看本地防火墙，最后换一个客户端试。三步做完基本能定位。</p>

<h2>运行几分钟就失败：心跳或认证</h2>
<p>能连上说明配置正确，几分钟后断开说明会话维持有问题。常见原因是心跳间隔太长，中间设备提前回收了连接；或者认证令牌过期，服务端主动断开。</p>
<p>处理方法：心跳调到三十秒以内，检查是否有会话超时设置，必要时开启自动重连。</p>

<h2>运行几小时后失败：资源或限速</h2>
<p>这个时间点通常对应三件事：并发数累积到上限、流量触发阈值、或者服务端做了定时回收。</p>
<p>排查方法：看失败时是否伴随速度下降（限速特征），看当月流量是否接近额度（额度特征），看是否每天都在固定时间失败（定时回收特征）。</p>

<h2>偶尔失败：链路波动</h2>
<p>不定时、不规律，通常是本地网络波动或国际链路拥塞。特点是「过一会儿自己好了」。</p>
<p>处理方法：开监控记录失败时间点，一周后看是否有规律。有规律（比如都在晚高峰）就错峰，没规律就接受并加重试。</p>

<h2>命令行三步定位</h2>
<p>第一步，测目标站点的连通性和延迟，看是否有响应。第二步，查当前出口地址，看代理是否生效。第三步，查解析结果，看域名解析到哪个地区。</p>
<p>三步一分钟跑完，能区分「链路问题」「代理没生效」「解析问题」三类，比在界面里反复点快得多。</p>

<h2>哪些情况不是你的问题</h2>
<p>三种：目标站点本身在维护；该地址段被目标站点限制；上游线路故障。前两种换一条地址就能验证，第三种只能等或换供应商。</p>
<p>判断方法：换一条地址试同一站点。通了说明是原地址的问题，不通说明是站点或链路的问题。</p>

<h2>什么时候该停止自救</h2>
<p>排查超过两小时还没定位，就该找供应商了。联系时给三样东西：错误提示原文、做过的测试及结果、失败的具体时间点。信息给全，对方能直接查服务端日志。</p>
<p>硬扛着查，往往在浪费时间。有服务端日志的人一眼能看出来的问题，你在本地猜半天也猜不到。</p>

<h2>常见问题</h2>
<h3>重装系统有用吗</h3>
<p>基本没用。代理是应用层配置，重装只会让你从头再来一遍。极少数情况是系统网络栈损坏，但那种情况其他网络也会异常。</p>
<h3>换个客户端能解决吗</h3>
<p>能解决一部分。不同客户端的心跳和重连策略不同，某些兼容性问题换客户端就好了。</p>
<h3>手机和电脑同时失败</h3>
<p>说明问题在出口侧，不在设备侧。这种情况下直接联系供应商，别在两台设备上分别排查。</p>
<h3>需要抓包吗</h3>
<p>普通用户不需要。抓包适合定位复杂问题，但学习成本高。先用上面五步排查，绝大多数问题到不了这一步。</p>
